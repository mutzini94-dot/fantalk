01 · 배경 & 문제 Context

왜 지금, 별도의 소통 앱인가

엑셀방송에서 크루의 매출과 화력은 소수의 열혈시청자가 좌우한다. 하지만 이들과의 관계는 방송 플랫폼 채팅·오픈카톡·DM에 흩어져 있어, 방송이 꺼지면 관계도 끊긴다. 관리할 수 없는 관계는 이탈한다.

  • P1소통 창구가 파편화되어 있다방송 플랫폼 채팅, 오픈카톡, 인스타 DM에 흩어져 크루가 팬 한 명의 히스토리를 한눈에 볼 수 없다.
  • P2후원 이력과 대화가 분리돼 있다누가 얼마를 언제 후원했는지가 소통 맥락과 연결되지 않아, 열혈시청자를 알아보고 대우하기 어렵다.
  • P3팬을 등급으로 관리할 도구가 없다기존 열혈네이션의 등급 개념이 크루의 일상 소통 도구로 이어지지 못한다.
  • P4접속·복귀 타이밍을 놓친다단골 도네이터가 앱에 들어와도 크루가 알 방법이 없어, 관계를 다질 골든타임을 흘려보낸다.
🎯

한 줄 정의

열혈톡은 투네이션 후원 데이터를 등에 업은 크리에이터 전용 팬 관계 관리(CRM) + 메신저다. 후원이 곧 관계 맥락이 되고, 관계가 다시 후원으로 이어지는 선순환을 만든다.

02 · 목표 & 성공지표 Goals & KPI

무엇을 성공이라 부를 것인가

단순 메신저가 아니라 리텐션과 후원 전환을 움직이는 도구를 목표로 한다. 아래 지표를 북극성으로 삼는다.

G1

관계 일원화

흩어진 팬 소통을 한 곳으로 모아, 크루가 팬 1명의 후원·대화·등급을 하나의 프로필에서 관리한다.

리텐션 강화

방송 외 시간에도 접점을 유지해 열혈시청자의 이탈을 막고 복귀를 유도한다.

후원톡·등급 보상을 통해 소통이 자연스럽게 후원으로 이어지게 한다.

04 · 핵심 컨셉 Value Proposition

후원과 관계를 하나로 잇는 세 개의 기둥

PILLAR 01

맥락 있는 소통

모든 대화 옆에 후원 이력과 등급이 붙는다. 크루는 "이 사람이 누구인지" 알고 대화한다.

PILLAR 02

보이는 인정

후원이 등급·배지·전용방으로 즉시 보상된다. 팬은 자신의 기여가 눈에 보인다.

PILLAR 03

놓치지 않는 타이밍

접속·후원·복귀 이벤트를 실시간 알림으로. 관계를 다질 순간을 흘리지 않는다.

산정 방식

08 · 데이터 모델 Data Model

핵심 엔티티 개요

투네이션 후원 데이터를 팬 프로필의 등급·이력과 연결하는 것이 설계의 핵심이다.

엔티티핵심 필드관계
Userid, role(크리에이터/도네이터/매니저), 프로필, 푸시토큰1 : N Membership
Crewid, 이름, 브랜딩, 등급정책, 후원목표1 : N Channel · Membership
Membershipuser_id, crew_id, grade, 누적후원, 최근접속, 메모, 태그User × Crew · 등급의 주체
Channelid, crew_id, 타입(공개/1:1/등급전용), 최소등급1 : N Message
Messageid, channel_id, sender, 본문, 타입(일반/후원톡/시스템)후원톡 → Donation
Donationid, user_id, crew_id, 금액, 메시지, 결제상태, 시각투네이션 연동 · 등급 산정 입력
Gradecrew_id, 명칭, 임계값, 혜택, 정렬순서Crew별 정의 · Membership 참조
Notificationid, user_id, 타입(접속/후원/등급/복귀), payload, 읽음User 수신함

※ 기존 cash-donation-settlement-erd 정산 스키마와의 연동 지점(Donation)은 별도 정합성 검토 필요.

09 · 기술 아키텍처 Architecture

실시간 · 알림 · 후원 연동

Client
  • 모바일 앱React Native / Flutter
  • 역할별 UIcreator / donator 분기
  • 푸시 수신FCM · APNs
  • 로컬 캐시오프라인 메시지 큐
Realtime & API
  • 실시간 채팅WebSocket · Socket.IO
  • 프레즌스온라인/접속 상태 관리
  • REST/GraphQL프로필·등급·이력
  • 알림 디스패처이벤트 → 푸시 라우팅
Data & 연동
  • DBPostgreSQL + Redis(프레즌스)
  • 투네이션 후원Webhook · 후원 이벤트 수신
  • 등급 엔진누적 후원 → 티어 산정
  • 인증투네이션 계정 SSO
🔗

연동의 심장 — 후원 Webhook

투네이션에서 후원이 발생하면 Webhook으로 Donation 이벤트가 들어오고, 이 이벤트가 ①후원톡 카드 생성 → ②등급 재산정 → ③알림 발송을 동시에 트리거한다. 이 파이프라인이 앱의 차별점 전부를 관통한다.

12 · 리스크 & 대응 Risks

미리 짚을 위험

위험내용심각도대응
과열 후원 유도등급·경쟁 요소가 과도한 지출을 부추길 우려높음후원 한도 안내, 건전성 가이드, 미성년 보호
사생활·경계1:1·접속 알림이 과도한 사적 접촉/스토킹으로 악용높음접속 알림 옵트인, 차단·신고, 방해금지 시간
모더레이션 부담실시간 채팅의 악성·불법 콘텐츠 대응중간금칙어·슬로우모드·신고 큐, 매니저 권한 분담
